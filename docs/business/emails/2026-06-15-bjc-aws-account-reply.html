1. What AWS account to set up — and the steps to do it

Just one new, standalone AWS account in BJC's name. Here's the full setup, start to finish — steps 1–6 sit with BJC and are quick (your IT, with Medihost helping on the technical bits, can have them done in well under an hour), then I handle everything after that:

  1. Create the account. Go to aws.amazon.com → "Create an AWS Account". Use a BJC shared mailbox as the root email (e.g. aws@bjchealth.com.au — not a personal inbox), name it "BJC Health", and set a strong root password stored in BJC's password manager.
  2. Add billing. Enter BJC's payment details — AWS bills BJC directly for usage (small for this workload, and fully itemised). Choose the free "Basic Support" plan.
  3. Secure the root login. Turn on multi-factor authentication (MFA) for the root user and keep those credentials with BJC. Root is for emergencies only; day-to-day work uses scoped logins.
  4. Set the region to Sydney (Asia Pacific, ap-southeast-2). All your stored data lives here. The AI also uses Melbourne — both Australian data centres, so nothing leaves the country.
  5. Create a deployment role for me. I'll send a short script that creates a single, scoped, revocable access role I use to build the system inside your account. BJC stays the owner the whole time, and you can revoke my access at any moment.
  6. Send me two things: the account ID and that role's identifier. That's all I need to begin.
  7. Set a billing alert (optional, recommended) so BJC gets a heads-up if AWS spend ever changes — I can set this up for you.

So from BJC's side it's really just: create the account, add billing, lock down the root login, and grant me the deployment role.

Yes — end to end. Once the account exists and I have the deployment role, I do all of it: switch on the AI, deploy the app + dashboard (serverless — there's no server to patch or babysit), stand up the database, wire up the automatic outage alert, and configure the Microsoft sign-in and the bjchealth.com.au-only access restriction. The AWS side is all scripted (infrastructure-as-code) and documented for handover. I also build the Power Automate flow on your server that pulls PDFs from your mailboxes, sends them to the converter, and drops the finished HL7 files into Genie's import folder. Medihost's role is to provide the server capacity, the Genie import-folder access, the service account, and to confirm Genie's referral (REF) flag is enabled — the same kind of support they gave for your existing automation.
